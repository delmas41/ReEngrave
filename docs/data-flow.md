## How to read this

- PART 1 has one block per MARK (clef, notehead, beam ...): how it is found, what ink it claims, what it hands on, who reads it at each stage, what the file writes, which flags gate it, old readers still beside it, and its open gaps.
- PART 2 has one block per FACT (a `Q.` quantity on the record): who files it, who reads it, and its status.
- PART 3 lists every gap the code shows: starved consumers, double feeds, dead reason words, old readers beside new ones.
- `runs` / `OFF by default`: whether the reader's code is reached with every flag at its default.
- Statuses: **LIVE** filed by a live producer and read by a later stage; **READ-BUT-NEVER-FILED** a stage reads it and nothing files it (an abstention or a `wants` line is not a producer); **ONLY-BEHIND-AN-OFF-FLAG** a stage reads it, and every row that would file it is behind a flag that is off by default; **FILED-BUT-NEVER-READ** filed, and read by no stage (only a tool, a human or nobody reads it); **READ-ONLY-INSIDE-GATHER** filed and read only inside GATHER: no later stage sees it; **FILED-ONLY-OUTSIDE-THE-PIPELINE** filed only by a human reader outside the pipeline (`producers.OUT_OF_PIPELINE`), read by a stage; **NOT-IN-USE** named in `Q`; nothing files it and nothing reads it under the default flags.
- Found from: `ink` the raster itself; `box` a detector box (a box the detector never drew has no subject); `box+ink` a box measured against its own ink; `text` OCR; `catalog` a fact not read off this page; `record` bookkeeping on rows already filed.
- DECLARED (one table in `flow_map.MARKS`, checked against the code): the mark names, `found from`, which functions read each mark, old readers, and the `written` line. Everything else is DERIVED.
- Blind spots: a site is OFF only where a flag decides it (a variable set False on the default branch is not seen); detail keys match by bare name; nothing here runs a page.
