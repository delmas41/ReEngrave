# OMR data-source follow-ups — DoReMi & MUSCIMA++

**Date:** 2026-05-15
**Context:** Best run so far is yolov8l on 4 merged DeepScoresV2 shards (~8k images, imgsz=1280), reaching ~66% mAP50 on the DSv2 val set. `benchmarks/omr-phase3/comparison-trained.md` calls out two weaknesses: (1) DSv2 is synthetic engraved, real WTC/Beethoven scans have paper texture & skew, and (2) ~37% of our detections fall in `category=unknown` because `_CATEGORY_MAP` in `tools/omr/yolo_detector.py` only names ~50 of 208 SMuFL classes. This memo asks whether DoReMi or a public MUSCIMA++ checkpoint can move either needle.

---

## 1. Steinberg DoReMi

**Source:** https://github.com/steinbergmedia/DoReMi · last release v1.0 (2021-06-14), repo currently low-activity (~13 stars, 4 open issues). Paper: WoRMS 2021.

### Facts

| Property | Value |
|---|---|
| License | **Not stated in the repo** (no LICENSE file visible). README explicitly notes "about half of this dataset is copyright protected; we only include openly distributable scores in the final published dataset." Translation: the published subset is at least redistributable, but the formal license is unspecified — needs a direct email to Steinberg before commercial use. |
| Annotation format | **Custom XML, graph-based** (similar to MUNG / MUSCIMA++). Each object carries class, AABB (top, left, width, height), pixel mask, musical metadata (pitch, duration, MIDI), and `inlinks` / `outlinks` to related objects. Both "parsed-by-page" and "unparsed" XML variants ship. |
| Bounding boxes | Axis-aligned only (no OBB). |
| Classes | 94. Covers noteheads, stems, clefs, time signatures, accidentals, rests, beams, slurs, dynamics — strongly overlaps DSv2's 208. |
| Image style | **Synthetic engraved.** Generated by Dorico at 300 DPI, binarized to monochrome PNG (2475 × 3504). **Not real-world scans.** |
| Size | ~5,218 images (in the published v1.0 release) — README claims ~6,432 in the full collection. Annotations: "nearly a million" objects (≈42× MUSCIMA++ by object count). |
| Pretrained weights | README promises them ("pre-trained models trained in the whole dataset will also be published") — none shipped as of v1.0 and no later releases. |
| Releases page | Single v1.0 asset, currently shows an "Uh oh!" loading error on the assets section — may need a mirror or direct contact to obtain a working download. |

### Compatibility with our pipeline

[tools/omr/training/prepare_yolo_data.py](tools/omr/training/prepare_yolo_data.py) is tightly coupled to DSv2's COCO-style JSON (`a_bbox`, `o_bbox`, `categories` keyed by string id, etc.). DoReMi's per-page XML is **a different schema entirely** — a new parser is needed. The good news: AABB ↔ YOLO normalization (`bbox_to_yolo`, `write_yolo_labels`, `write_data_yaml`) and the train_yolo.py invocation are dataset-agnostic and would be reused as-is.

### Practical assessment

- **Worth integrating?** Yes, as additional training data for a multi-dataset run. The 94-class label space overlaps DSv2 — a class-name remap (DoReMi name → DSv2 id, fall through to `null`/skip for non-overlap) lets us mix the two corpora and train a single model on the union. Could plausibly push mAP50 a few points and reduce per-class data starvation on rarer symbols. **Will not** close the synthetic→real gap on its own (DoReMi is also Dorico-generated, just like DSv2 is Mscore-generated).
- **Effort:** **Medium.** New XML parser (~200–300 LoC: walk Object nodes, pull `Top/Left/Width/Height`, build the YOLO `.txt`). Plus a class-name remap (a small JSON dict). Plus dataset acquisition (release-page assets are currently broken — may need to email Steinberg). Plus a fresh ~4–8h training run on the merged corpus.
- **Blockers:**
  1. License ambiguity — must confirm with Steinberg before any commercial deployment.
  2. Releases page asset download is currently broken.
  3. Synthetic-only — doesn't address the real-scan gap, which is the more important phase-3 weakness.

## 2. Public MUSCIMA++ YOLO checkpoints

**Background:** The "Eric Shen ~72% mAP50" line in `comparison-trained.md:69` references his Medium article ([sheneric211/a-tale-of-two-techniques…](https://medium.com/@sheneric211/a-tale-of-two-techniques-comparing-deep-learning-optical-music-recognition-with-ultralytics-yolov8-34b40f2d3bdf)) and the team repo at https://github.com/dmgonzalez8/OMR. **That work was trained on DeepScoresV2-dense, not MUSCIMA++.** So the implied premise — "a public MUSCIMA++ checkpoint at ~72% mAP50" — is incorrect; that number is on the same dataset we're already using, just at a smaller imgsz ([704, 992]) with YOLOv8x.

### Public weights actually trained on MUSCIMA++

After a fair search (GitHub, HuggingFace, arXiv linkbacks): **none that I can find.** Specifically:

- **Yang et al. 2024 — "Toward a More Complete OMR Solution"** ([arXiv 2409.00316](https://arxiv.org/abs/2409.00316)) — trains a YOLOv8 detector on MUSCIMA++ v2.0 and beats prior work, but the paper does **not** link a code repo or release weights. Authors at UW / AI2.
- **Hajič et al. — MUSCIMA++ baselines** — Faster R-CNN era, no YOLOv8 release.
- **HuggingFace** — no MUSCIMA++-specific YOLO model when filtering on `music`, `omr`, `muscima`. Only generic / face / signature YOLOs.
- **`v-dvorak/omr-layout-analysis`** ([github.com/v-dvorak/omr-layout-analysis](https://github.com/v-dvorak/omr-layout-analysis)) — has a pretrained YOLOv8 (MIT-licensed, latest release April 2025), but it detects **layout structure only** (staves, systems, measures, grand-staves — 5 classes). Different problem from symbol detection; **not** a checkpoint we can fine-tune for individual symbols.
- **Eric Shen / dmgonzalez8/OMR** — `YOLOv8x @ imgsz=[704, 992]`, 72.8% mAP50 on DSv2-dense, weights on a public Google Drive folder ([drive.google.com/…/13Z64ReEJGlMnCqPkA-dcCD8tzdtvLyqO](https://drive.google.com/drive/folders/13Z64ReEJGlMnCqPkA-dcCD8tzdtvLyqO?usp=sharing)). **No LICENSE file** in the repo — defaults to all-rights-reserved under copyright. Useful as a comparison baseline; redistribution / fine-tuning into a commercial product is legally uncertain without permission from the authors.

### MUSCIMA++ dataset itself (if we wanted to train our own)

| Property | Value |
|---|---|
| License | **CC-BY-NC-SA 4.0** — **non-commercial only**, plus share-alike. ReEngrave charges $5/score, so this is a hard blocker for production. |
| Annotation format | Custom XML (`<Node>` elements: class, AABB, pixel mask, inlinks/outlinks). Not COCO — needs a new parser. |
| Bounding boxes | Axis-aligned. |
| Classes | 163 (often filtered to ~73 "essential" for OMR). Different label space from DSv2's 208 — transfer learning would need a head reset; only backbone weights are reusable. |
| Image style | **Handwritten real scans.** CVC-MUSCIMA: 20 pages, each re-written by 50 musicians, binarized, staves removed. Domain-different from our engraved WTC/Beethoven target. |
| Size | 140 annotated images, 91,255 symbol annotations. |
| Latest version | v2.1 (Feb 2025), at `http://hdl.handle.net/11372/LRT-2372`. |

### Practical assessment

- **Worth integrating?** **Not for transfer-learning weights** — there's no usable public checkpoint, and the one paper that has one hasn't released it. **Possibly for backbone-only pretraining** if we wanted handwriting robustness, but our target (WTC, Beethoven) is engraved, not handwritten, so this is a poor domain match.
- **Effort:** **Large.** Would require (a) writing a MUSCIMA++ XML → YOLO converter, (b) training our own checkpoint from scratch (no pretrained shortcut exists), (c) navigating the CC-BY-NC-SA license — which alone disqualifies it from anything we ship commercially.
- **Blockers:**
  1. **License** is the showstopper for a paid product. Both the dataset and any derivative model are restricted to non-commercial use.
  2. **No public weights.** All the "MUSCIMA++ YOLOv8" hits in search are papers without code release.
  3. **Domain mismatch.** Handwritten + staff-line-removed ≠ engraved scanned PDFs. The published benchmarks (~59.7% mAP on dense, ~72% on simpler splits) don't transfer in any obvious way to our engraved domain.

---

## Summary

**DoReMi is the higher-value follow-up.** It is *plausibly* additive to DSv2 training (synthetic engraved, ~5k more images, 94 classes that overlap DSv2's label space) with medium integration effort and only a license-clarification email as a real blocker. MUSCIMA++ is a research-only dataset with no public YOLOv8 checkpoint and a handwriting domain mismatch — interesting academically, but neither the data nor any released weights are usable as-is for ReEngrave's engraved-score target. The bigger win for closing the synthetic→real gap is almost certainly **fine-tuning on a small hand-labeled set of real WTC/Beethoven scans**, not either of these datasets.
