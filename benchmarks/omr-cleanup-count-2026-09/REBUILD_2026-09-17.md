# The artefact rebuilt on today's tree — and the builder was BROKEN on main

The first count's artefact was built 2026-09-11. Eight repairs have landed
since. This rebuilds it on the same four pages from a fresh record so the
question *"how much work would I have to do to clean it up"* is asked of
today's output — and **the gather was already paid for**, so the whole rebuild
is seconds.

```bash
R=library/_shared-records/beethoven5-p1-p4-ink-identity.record.json   # md5 ea80ae59…
TAG=p1-p4-2026-09-17
python3 benchmarks/omr-cleanup-count-2026-09/export_arm.py      --record "$R" --tag $TAG
python3 benchmarks/omr-cleanup-count-2026-09/build_sheet.py     --record "$R" --tag $TAG
python3 benchmarks/omr-cleanup-count-2026-09/build_sidebyside.py --record "$R" --tag $TAG
```

⚠️⚠️ **THE BUILDER DID NOT RUN, AND ITS OWN CONTROLS ARE WHY THAT IS KNOWN
RATHER THAN SHIPPED.** Three separate failures, in order:

1. **`NameError: starts` — `export_arm.system_map` raised on every run.** The
   2026-09-14 document-numbering repair computed `first`/`last` from
   `_document_bar_offsets` and **left the two pre-repair lines below it**,
   which overwrote both from a `starts` dict that no longer exists. The
   per-part fallback also read `n` before assignment. So the system map — the
   piece that tells a human WHICH BARS to look at — could not be built at all,
   and had not been since that repair.
2. **The map disagreed with the file on 2,924 (part, measure) pairs**, which
   is *exactly* the run's own `tacet_bars_padded`. The map walked each part's
   `StaffRun`s, and since the 2026-09-15 tacet repair the exporter **writes
   bars for systems a part is not printed on**, which belong to no run. The
   control was RIGHT and the map was incomplete: it now walks the exporter's
   own `_tacet_walk`, and every padded row carries **`tacet: true`** — the
   field the human needs, because those bars are in the FILE and not on the
   PRINT and are never a fix-action.
3. **`build_sheet`'s decomposition was three repairs stale.** Its docstring
   said *"mirrors `_place_notes`' three refusals in order"*; there are now
   five. It had never heard of `ink_is_a_whole_rest` or
   `owned_by_another_staff`, so it counted **542** held-back notes where the
   exporter refuses **738** — and its control refused to write rather than
   hand over wrong proposals.

⚠️ **All three are the same fault: a rule held twice.** Each is repaired by
deleting the copy, not by patching it — `system_map` already made that move
for `_document_bar_offsets` and says so in its own comment. `_place_notes` now
counts refusals **per printed system** as well as per reason, through ONE
helper so a refusal added later cannot reach one counter and miss the other,
and `build()` asserts the two **sum**. `_spans_from_numbering` is extracted so
the padding and the map cannot disagree about a system's bar count.

⚠️ `export_arm` now stamps `export_provenance` — the tree AND settings of the
EXPORTING process — closing the gap FINDINGS.md named: *"the base arm is not
the artefact Sean looked at and the difference cannot be attributed."*
All three scripts now take `--record`; two of them hardcoded a path the third
did not.

while a fragment pairs with nothing and is obvious. This is that choice,
visible in an artefact for the first time.

## Reading the artefact

**`out/side-by-side-p1-p4-2026-09-17.html`** — 7 printed systems, print above
our output, worst-first, crops embedded (8.6 MB, self-contained).
**`out/counting-sheet-p1-p4-2026-09-17.csv`** — one row per printed staff.

⚠️ **THE ROWS ARE ORDERED TOP-TO-BOTTOM (`staff_slot_top_to_bottom`) AND THE
NAMES ARE NOT USEFUL.** Every `part_name` reads `Staff p2-s0-7` and the like,
because `instrument` still abstains — the first count's third defect, UNFIXED.
Count by the SLOT column, never by the name.

⚠️ `bars_PRINTED_on_this_system` and `measures_in_file` differ by one on these
pages (98-112 against 97-111). Both columns are shown deliberately so the
mapping is visible; use the printed column to find the bar on the plate and
the file column to find it in the XML.

⚠️ **Only `proposed_*` is pre-filled, and only about ABSENCE.**
`proposed_spurious` is null on every row BY DESIGN: deciding it needs the
print, and the machine has not got one. **Never add a `proposed_` column into
a total.**

⚠️ **REACH: pdf pages 1-4 of ~16, 7 printed systems, reference mm 1-112 of
502 (22.3%)** — bounded by the last hand-verified window row, past which
nobody has checked which printed bar a system starts at. And this is the
**pessimistic** end of the corpus: Litolff `984073` is the low-res bitonal
scan, which fires 49 flag boxes against Breitkopf's 371.

⚠️ Verovio reports **13 and 10 ties left open** on two systems while
rendering. That is the known tie-pairing defect (a quarter of tie pairings
bind two different pitches; 63 of 91 tie starts resolve onto nothing), not
something this rebuild introduced.

## ⚠️⚠️ A FOURTH COPY OF THE SAME RULE, FOUND AND NOT FIXED

`grep -rn _place_notes` turns up
`benchmarks/omr-arc-recovery-2026-09/arc_partition.py:44`, whose docstring
reads *"What `_place_notes` did with this notehead row, **by ITS OWN branch
order**"* and *"The order is `_place_notes`'s and must stay it"*. That is a
fourth hand-written copy of the refusal sequence — after `build_sheet`'s
(three repairs stale, repaired here), `system_map`'s per-part numbering
(repaired 2026-09-14) and the `spans` projection (repaired here).

**It is not fixed**, because it belongs to another benchmark's arms and
changing it would move figures that job published. It is recorded so the next
reader of that file knows the rule it copies now has a single source
(`report["notes_not_written_by_system"]`) and five branches, not three.

**The generalisation, which is the finding of this rebuild:** every one of the
four copies was written for a good local reason, and **three of the four had
silently gone stale** by the time anyone looked. A rule that decides what
reaches a file will be copied by whatever needs to explain the file, and the
copies do not fail loudly — they produce a plausible smaller number.
